# 模块设计

> 每个模块独立 crate,`src/` 内按职责分子模块文件;模块间通过 Core 消息总线解耦。

## Core —— 负责协调总体

| 文件 | 职责 |
| --- | --- |
| `coordinator.rs` | 总协调器:挂载/启停/降级模块,广播生命周期事件 |
| `message.rs` | 消息总线:`Message{from,to,topic,payload,ts}` + broadcast 通道 |
| `registry.rs` | 模块注册表:`ModuleInfo{id,label,version,status,note}` |

关键类型:
```rust
pub enum ModuleStatus { Stopped, Starting, Running, Degraded, Failed }
pub struct Message { pub from: String, pub to: String, pub topic: String, pub payload: Value, pub ts: u64 }
```

## NetLinker —— 网络设备连接程序

| 文件 | 职责 |
| --- | --- |
| `device.rs` | 统一设备模型:`Device{id,name,kind,address,state,last_seen,attrs,trusted}` |
| `registry.rs` | 设备注册中心:`RwLock<HashMap>` 并发台账,心跳续期、按种类过滤 |
| `connector.rs` | 连接状态机:`Idle/Connecting/Connected/Reconnecting/Disconnected` + 指数退避 |

设备种类:`contact`(门磁)/ `presence`(人体)/ `camera` / `lock` / `gateway` / `sensor` / `actuator` / `unknown`。

## NetScanear —— 网络设备发现程序

| 文件 | 职责 |
| --- | --- |
| `scanner.rs` | 并发 TCP 端口探测(线程池 + `connect_timeout`),反查主机名 |
| `discovery.rs` | 扫描结果 vs 白名单,产出陌生设备报告 |

`ScanConfig` 默认探测端口:`22, 80, 443, 445, 3389, 8123(HA), 1883(MQTT), 554(RTSP)`。

## SideAgent —— 边缘AI模型

| 文件 | 职责 |
| --- | --- |
| `model.rs` | `ModelInfo{id,name,kind,format,path,status,avg_latency_ms}`;种类:detection/classification/gesture/behavior/rule |
| `registry.rs` | 模型注册表:加载/卸载/状态/推理耗时滑动平均 |
| `runtime.rs` | `ModelRuntime` trait + `RuleRuntime`(欧氏距离模板匹配,零依赖) |

ONNX YOLO 等权重模型按 `ModelRuntime`/`Detector` trait 接入,`runtime.rs` 中 `predict_rule()` 已可直接用于手势分类演示。

## HandModel —— 模块控制程序

| 文件 | 职责 |
| --- | --- |
| `params.rs` | 参数定义与取值:`ParamValue::{Int,Float,Bool,Text}`(serde tag 强类型) |
| `control.rs` | `Controller`:注册/启动/停止/下发参数/记录状态 |

## VEScaner —— 视频设备发现程序

| 文件 | 职责 |
| --- | --- |
| `probe.rs` | 网段内 RTSP(554)/ ONVIF(8000)端口探测,生成视频设备台账 |
| `frame.rs` | 灰度帧差运动检测:`MotionReport{changed_ratio,moving,bbox}` |

## YololookUP —— 视频粗略代审计模块

| 文件 | 职责 |
| --- | --- |
| `detect.rs` | `Detector` trait(输入灰度帧 → 检测列表)+ `NoopDetector` 优雅降级 |
| `audit.rs` | `AuditEngine`:关键目标(person/car)命中 + 运动 → Critical;仅目标 → Suspicious |

审计规则(默认):
- `min_confidence = 0.55`,`motion_threshold = 0.02`;
- 命中 `watch_labels` 且画面运动 → `critical`;
- 仅命中目标 → `suspicious`;仅运动 → `info`。

## SelflookUP —— 自我审计程序

| 文件 | 职责 |
| --- | --- |
| `health.rs` | 健康检查:`CheckItem{name,status,detail}`;总体 = 最差单项 |
| `audit_log.rs` | 审计日志:只追加环形缓冲,按操作者过滤 |

## ATOGrowUP —— 自发成长和变异程序

| 文件 | 职责 |
| --- | --- |
| `profile.rs` | 行为画像:设备 × 小时活跃计数、`activity_curve()`、异常活跃建议(均值 ×3 且 ≥3 次) |
| `evolve.rs` | 规则变异:`RuleGene{kind,start_hour,end_hour,fitness,generation}`;精英保留 + 小时漂移 ±2 + 种类翻转 |

进化策略:
1. 按适应度降序排序,保留前 50% 精英;
2. 尾部基因变异:时段漂移 ±2 小时,按变异率翻转 Arm/Disarm;
3. 变异后代适应度 ×0.9,等待真实命中反馈(`reward()` 提升/降低)。

## AUTOTIME —— 定时和节律控制

| 文件 | 职责 |
| --- | --- |
| `schedule.rs` | 类 Cron 规则:`分 时 日 月 星期`,支持 `* / */n a,b a-b`,公历换算零依赖 |
| `rhythm.rs` | 昼夜节律:24 小时活跃曲线、归一化、低活跃窗口推荐布防时段 |

## Server —— 负责管理网页和内核桥接的服务

| 文件 | 职责 |
| --- | --- |
| `main.rs` | 装配:配置 → 状态 → 模块挂载 → MQTT/周期任务 → axum 路由 |
| `mqtt.rs` | MQTT 桥接:订阅 `pilhome/+/event`,自动建档 + 事件 + 画像;命令通道 |
| `ha/discovery.rs` | HA MQTT Discovery:设备 → `homeassistant/<platform>/pilhome_<id>/config` 保留消息 |
| `tasks.rs` | 周期任务:定时命中、扫描、进化、健康、快照、Webhook |
| `persistence.rs` | JSON 快照持久化与启动恢复 |
| `webhook.rs` | 零依赖 HTTP 告警推送 |
| `api/` | REST 路由(见 08-API参考.md) |
