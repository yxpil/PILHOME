# 边缘 AI 推理

## 一、设计原则

1. **本地优先**:推理全部在边缘网关内完成,视频帧、传感器数据不出内网;
2. **可插拔后端**:统一 `trait`,规则引擎与 ONNX/TFLite 权重模型无缝切换;
3. **优雅降级**:模型未配置权重时(`NoopDetector`/`RuleRuntime`)系统照常运行,仅 AI 能力降级;
4. **可观测**:模型注册表记录平均推理延迟(`avg_latency_ms`,滑动平均 0.9/0.1)。

## 二、模型管理(SideAgent)

```
POST /api/models {id, name, kind, format, path}
        │
        ▼
ModelRegistry.register() ──▶ ModelStatus::Ready
        │
        ▼
YololookUP / 其他模块 按 id 取模型,调用 ModelRuntime::run()
```

模型种类:`detection`(目标检测)/ `classification` / `gesture`(手势)/ `behavior`(行为)/ `rule`(规则引擎)。

内置模型(启动时注册):
| id | 名称 | 种类 | 格式 | 权重路径 |
| --- | --- | --- | --- | --- |
| `yolo_v8n_person` | 人员检测 YOLOv8n | detection | onnx | `models/yolov8n.onnx` |
| `gesture_rule` | 手势识别规则引擎 | gesture | rule | `builtin` |

## 三、规则引擎(RuleRuntime)

8 维归一化手指开合特征,与内置模板(握拳/张手/OK/比耶)计算欧氏距离:

```rust
confidence = (1.0 - distance / 2.0).clamp(0.0, 1.0)
```

零依赖、毫秒级,适合边缘 CPU;可用于"手势布防/撤防"交互验证。

## 四、YOLO 视频审计(YololookUP)

流水线:`VEScaner 抓帧 → FrameDiff 帧差(运动比例)→ YololookUP::audit_frame → 审计事件`

| 输入 | 输出 |
| --- | --- |
| 灰度帧 + 宽高 + 运动比例 | `AuditEvent{ts, camera_id, level, summary, detections}` |

判定规则:
- 命中 `person`/`car` 且 `confidence ≥ 0.55` 且画面运动 → `critical`;
- 仅命中关键目标 → `suspicious`;
- 仅运动 → `info`。

接入真实 YOLO 模型:实现 `Detector` trait(`detect(frame, w, h) -> Vec<Detection>`),
内部用 ONNX Runtime 加载 `yolov8n.onnx`,NMS 后输出检测框即可。

## 五、行为画像与节律(ATOGrowUP × AUTOTIME)

1. 每条设备事件按 `(device_id, hour)` 累计;
2. `activity_curve(device)` 输出 24 小时活跃期望(按观察天数归一);
3. 多设备聚合 → `RhythmCurve` → 低活跃窗口(<0.2)推荐为布防时段;
4. 异常识别:当前小时活跃 ≥ 历史均值 ×3 且 ≥3 次 → alert 建议。

## 六、规则变异(ATOGrowUP::Evolver)

```
种子规则 → [每代] 适应度排序 → 精英保留 50% → 尾部变异(时段漂移±2h / 种类翻转)
        ↕ 真实命中 reward(+)/误报 reward(-) 反馈
```

变异率 0.15,后代适应度 ×0.9 抑制劣化,系统随家庭作息变化"自发成长"。

## 七、隐私与性能

| 指标 | 说明 |
| --- | --- |
| 数据本地化 | 帧/事件不离开内网,仅告警摘要可选上送 HA |
| 推理延迟 | 规则引擎 <1ms;ONNX YOLOv8n CPU 约 30-80ms/帧 |
| 资源占用 | 全 Rust 静态编译,常驻内存 <50MB(不含模型权重) |
| 正确性 | 规则引擎/帧差/画像/进化均有单元测试(cargo test 全绿) |
