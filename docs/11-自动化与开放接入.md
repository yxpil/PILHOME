# 自动化引擎与开放接入

PILHOME 不依赖任何外部平台即可完成闭环:**内置自动化引擎**(等价于 HA 的
Automation)+ **开放接口**(WebSocket 事件流 / MQTT 发布 / REST),外部系统
(HA、自定义脚本、手机 App、其他网关)均可接入 PILHOME。

## 一、内置自动化引擎

### 1.1 规则模型

```
规则 = 触发器(事件匹配) + 条件(时间窗口) + 动作列表
```

| 组成 | 字段 | 说明 |
| --- | --- | --- |
| 触发器 | `device_id` | 设备 ID(空 = 任意) |
| | `key` | 事件键(如 `contact` / `motion`) |
| | `value` | 事件值(如 `open`) |
| | `min_level` | 最低级别(info/warn/alert) |
| 条件 | `window` | 小时窗口 `(start, end)`(空 = 全天) |
| 动作 | `log` | 记录系统事件 |
| | `mqtt` | 发布 MQTT 消息(topic + payload) |
| | `ha` | 调用 HA 服务(entity_id + action) |
| | `webhook` | 发送 HTTP 告警(url) |

### 1.2 示例

```bash
# 夜间(22:00-06:00)门磁触发 → 记录告警 + 开客厅灯 + Webhook 通知
curl -X POST localhost:8080/api/automations -H "Content-Type: application/json" -d '{
  "name": "夜间门磁告警",
  "device_id": "contact_front_door",
  "key": "contact",
  "value": "open",
  "action_type": "ha",
  "entity_id": "light.living_room",
  "action": "on"
}'

# 任意 alert 级事件 → 发 MQTT 给报警器
curl -X POST localhost:8080/api/automations -H "Content-Type: application/json" -d '{
  "name": "告警联动报警器",
  "min_level": "alert",
  "action_type": "mqtt",
  "topic": "pilhome/siren/command",
  "payload": "on"
}'
```

### 1.3 规则管理 API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/automations` | 规则列表 |
| POST | `/api/automations` | 新增规则 |
| POST | `/api/automations/{id}/toggle` | 启用/停用 |
| DELETE | `/api/automations/{id}` | 删除规则 |

引擎每秒增量扫描事件流,命中即顺序执行动作。

## 二、WebSocket 实时事件流(对外开放)

**任意客户端可连接 `ws://<host>:8080/api/ws`,实时接收 PILHOME 全量事件。**

```bash
# 命令行演示(wscat 或 node)
node -e '
const ws = new WebSocket("ws://127.0.0.1:8080/api/ws");
ws.onmessage = (m) => console.log(m.data);
'
```

连接后立即收到握手:
```json
{ "type": "auth_ok", "system": { "name": "PILHOME 边缘网关", "version": "0.1.0" } }
```

随后每条事件实时推送:
```json
{ "type": "event", "data": { "ts": 1785900000, "level": "alert", "source": "netscanear", "message": "发现 1 台陌生设备", "device_id": null, "data": null } }
```

保活:客户端发送 `ping`,服务端回 `pong`。

**接入场景**:
- 手机 App 订阅告警;
- HA 自动化经 WebSocket 读取 PILHOME 事件(或经 MQTT,二选一);
- 其他网关/脚本作为下游消费者。

## 三、MQTT 发布接口(经网关下发)

```bash
curl -X POST localhost:8080/api/mqtt/publish -H "Content-Type: application/json" \
  -d '{"topic":"pilhome/siren/command","payload":"on"}'
```

外部系统无需直连 broker,统一经 PILHOME 审计留痕后下发。

## 五、与 Home Assistant 的关系

| 能力 | PILHOME 内置 | HA 侧(可选) |
| --- | --- | --- |
| 设备接入 | MQTT / 网络发现 / 视频发现 | 双向桥全量同步(上千种设备) |
| 自动化 | ✅ 内置引擎(事件触发+动作) | 可复用其复杂场景(条件/嵌套) |
| 场景 | ✅ 布防/撤防/离家/回家 | 可联动 |
| 状态历史 | ✅ 事件持久化(JSON 快照) | 可读事件流 |
| 实时事件 | ✅ WebSocket 开放流 | 可订阅 |
| 控制下发 | ✅ REST / MQTT | 可调用 |

**两种形态**:
1. **独立闭环**:PILHOME 单机运行(无 HA),自动化引擎 + 场景 + 告警全自持;
2. **HA 共存**:PILHOME 接管 HA 全屋设备(双向桥),HA 作为设备接入层与复杂联动层,两者互为上下游。

## 六、安全提示

- `/api/ws` 与 REST 默认仅监听回环(127.0.0.1);对外暴露需置于 VPN/防火墙后;
- WebSocket 事件含设备行为数据,勿公网裸奔;
- MQTT 发布接口建议加网关侧鉴权(后续版本可加 token)。
