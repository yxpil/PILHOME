# 安全设计

## 一、威胁模型

| 威胁 | 应对模块 |
| --- | --- |
| 陌生设备接入内网 | NetScanear 周期扫描 + 白名单对比,陌生主机触发 alert |
| 门磁/传感器被撬或异常触发 | ATOGrowUP 行为画像,异常时段活跃度告警 |
| 夜间入侵 | AUTOTIME 节律推荐布防窗口 + YololookUP 视频审计 |
| 摄像头画面被滥用 | 视频帧仅本地处理,AI 推理不出网关 |
| 配置/操作被篡改 | SelflookUP 审计日志只追加留痕 |
| 模块故障静默 | SelflookUP 健康检查 + 事件总线告警 |

## 二、纵深防御层次

```
┌─ 应用层:WebUI 走本地回环,静态资源无脚本注入面(原生 TS 构建)   ┐
├─ 服务层:API 全部强类型校验;审计日志记录每次关键操作             │
├─ 核心层:模块注册表状态机(Stopped→Running→Degraded→Failed)     │
├─ 感知层:设备白名单 + 心跳超时离线判定(120s)                    │
└─ 网络层:陌生设备扫描告警 + MQTT 主题权限最小化                  ┘
```

## 三、关键机制

### 3.1 陌生设备识别
- 周期扫描网段(默认 600s),对照 `trusted` 白名单;
- 陌生主机:IP、开放端口、主机名进入 `DiscoveryReport` 并产生 alert 事件;
- WebUI 一键"信任"设备,加入白名单。

### 3.2 行为异常识别
- 设备 × 时段画像,异常判定:`当前 ≥ 历史均值 ×3 且 ≥3 次`;
- 新设备样本不足(总事件 <8)不下结论,避免误报。

### 3.3 审计留痕(SelflookUP)
- 关键操作(设备注册/信任、模块启停、模型加载、规则添加、扫描执行)全部写入审计日志;
- 只追加、环形缓冲,可追溯操作者与时间。

### 3.4 健康自检
- 周期检查设备在线率,在线率下降 → warn 事件;
- 模块状态机异常(Degraded/Failed)由 Core 广播。

### 3.5 数据安全
- 事件、画像、审计默认仅存内存(环形缓冲),落盘按 `data_dir` 配置;
- 视频帧只做内存计算,不持久化;
- 敏感配置(token 等)建议经环境变量注入,不进版本库。

## 四、MQTT 安全建议

1. Mosquitto 开启账号认证,网关使用独立账号;
2. 按主题 ACL:`pilhome/#` 仅授权客户端可读写;
3. 内网隔离:网关建议部署在独立 VLAN 或防火墙后;
4. 若需远程访问,优先 VPN/SSH 隧道,勿直接暴露 8080 端口。

## 五、合规提示(毕设使用)

- 摄像头采集需在家庭内部环境运行,遵循个人隐私保护要求;
- 若涉及公共区域采集,需取得相关授权;
- 审计日志与行为画像仅用于本地安防决策,不对外提供。
